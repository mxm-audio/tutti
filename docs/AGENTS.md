# AGENTS.md — docs

# Purpose

What a reader of the format reads besides the spec: `research.md` (the findings of 2026-10-20
the format was designed from, with sources), `agent-guide.md` (what a program or an agent reads
first: reading and writing a project, the time model and the model in a paragraph each, the
smallest document, common tasks, pitfalls; `llms.txt` at the root points here), and
`field-reference.md` (generated from the schema). The implementers' guide comes with the
closeout stage.

# Ownership

Owns every file here. `field-reference.md` is generated by `tutti-schema`'s `fields` binary and
committed; a test fails when it is stale.

# Local Contracts

- **The agent guide is `agent-guide.md`, never `agents.md`**: on a case-insensitive file system
  (Windows, macOS by default) `docs/agents.md` and this `AGENTS.md` are one file, and the guide
  overwrote the DOX once (2026-10-21). Its URL is `tutti::AGENTS_URL`, which every project
  README carries, and the `archive` command copies it as `spec/agent-guide.md`.
- The guide only points: the normative text is the spec, the schema is the schema. A number
  stated here is the spec's, by reference.
- `research.md` is a record: what was read on its date, judgements marked as such. It is not
  updated to match the design; the design's reasons are `NOTES.md`.

# Work Guidance

- A new core function or a changed rule reaches the guide's "common tasks" when an agent would
  look for it there.

# Verification

- `cargo test -p tutti-schema` (the field reference current, the guide's examples valid where
  the tests cover them).
